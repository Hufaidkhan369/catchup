# CatchUp — "What did I miss?"

A **local-first AI micro-app** that helps you quickly understand busy group chats: it summarises
long or unread conversations, extracts the decisions and action items, works out what is *urgent*
and personally **relevant to you**, and shows what you **may have missed**.

**No conversation, no summary and no slice of your data ever leaves the browser.** All processing
happens on your device. That is not a badge — it is the architecture (see below).

---

## TL;DR of the features

| # | Feature | Where it lives |
|---|---------|----------------|
| 1 | Import chats (paste, `.txt` WhatsApp/Telegram export, `.json` Slack export) + **"Load demo chat"** (150+ realistic college project-team messages) | `src/lib/parser.ts`, `src/lib/demoChat.ts` |
| 2 | Short **TL;DR** + **topic-wise breakdown** for long/unread conversations | `src/lib/summarize.ts` |
| 3 | **Key extraction** — decisions, action items (task · owner · deadline), announcements | `src/lib/extract.ts` |
| 4 | **Explainable priority** High / Medium / Low with a "Why?" tooltip (deadline proximity, urgent words, your mentions/tasks) | `src/lib/priority.ts` |
| 5 | **"You may have missed"** — mentions of you, questions aimed at you, unanswered requests | `Mentions` tab |
| 6 | **User profile** (name/@handle/tasks) personalises relevance | `ProfilePanel` |
| 7 | **Filters & tools** — filter by priority/type/sender, search, mark actions done, export as Markdown or text | `FilterBar`, `ItemCard`, `lib/export.ts` |
| 8 | **Catch-up window** — "last 1h / 6h / 24h / custom / all", plus an *unread divider* in the chat view | `CatchupWindowPicker`, `ChatView` |
| 9 | **Explainable priority ("Why?")** — every badge shows its score contributions | `PriorityBadge` |
| 10 | **Decision updates** — when "Meeting moved Mon → Wed", you get **only the latest version** with tap-to-expand history | `src/lib/decisionUpdates.ts` |
| 11 | **Message context viewer** — tap an item to see the original message ±3 | `MessageContextModal` |
| 12 | **Smart reply drafts** — 2–3 short, copyable on-device replies for questions aimed at you | `src/lib/replyDrafts.ts` |

**Privacy (must-have):**
- 100% on-device badge + offline indicator in the header.
- AI engines used: **Gemini Nano** (Chrome's built-in Prompt API) → **WebLLM** (optional download
  of open model weights, run in WebGPU) → **deterministic rule-based fallback**. The active engine
  is shown in the header and in the engine panel, so "is this really AI?" is always verifiable.
- Data stored only in **memory or IndexedDB**, with a **"Clear all data"** button.
- OTPs, phone numbers and card numbers are **masked in summaries, exports and drafts**.
- No backend, no analytics, no third-party API calls with your chat. The only network traffic is
  the optional WebLLM model *file* download (never chat content).

## Architecture (local-first)

```
                       ┌──────────────────────────────────────────────┐
  WhatsApp/Telegram/   │                  Browser (client only)        │
  Slack export / paste │                                              │
  ───────────────────► │  parser.ts ─► Messages ─┬─► extract.ts       │
                       │                          │      │  (decisions, │
                       │                          │      │   actions,   │
                       │                          │      │   mentions)  │
                       │                          ├─► priority.ts      │
                       │                          │      └┬─► actions/  │
                       │                          │        decisions    │
                       │                          │                    │
                       │                          └─► summarize.ts      │
                       │                                │  ┌────────────┼─────────┐
                       │                                ▼  ▼            ▼         ▼
                       │                     Gemini Nano / WebLLM   rule-based  IndexedDB
                       │                     (on-device LLM or      extractive  (profile,
                       │                      rule-based fallback)  topics)     messages,
                       └──────────────────────────────────────────────────────── done items
```

Key principles:

1. **Deterministic pipeline first.** Parsing, extraction, priority scoring and decision-update
   resolution are pure TypeScript functions with unit tests. They always run and always work —
   with or without a model.
2. **The model upgrades the summary, never fakes it.** When a neural engine is available the
   TL;DR is generated by a real on-device model call (chunked map → reduce for long chats).
   Topic breakdown stays rule-based for accuracy. If the model call fails, we fall back
   deterministically and *tell you* the engine that actually ran.
3. **Chunking** (`chunkMessages`) keeps prompts within the model's context window for long chats.
4. **Everything is testable.** `src/lib/**/*.test.ts` — run with `npm test`.

### Adding the demo / why demo data is not "fake output"

`demoChat.ts` is **input data**, like pasting an export. Every summary, decision, action item,
priority and mention you see is computed at runtime by the pipeline above. Nothing in the UI is a
hard-coded result. This is deliberate and important for hackathon evaluation: unplug the demo and
paste your own WhatsApp export — the same features run on your data.

## Quick start

```bash
npm install
npm run dev        # local dev server
npm test           # 44 unit tests for parsing, privacy, priority, extraction, ...
npm run build      # type-check + production build in dist/
npm run preview    # preview the production build
```

Open the printed `http://localhost:5173`, click **Load demo chat**, pick a catch-up window and
**Analyse chat**.

### Enabling a real neural model

- **Gemini Nano** — open in **Chrome 138+** (desktop). CatchUp auto-detects the Prompt API
  (`LanguageModel`) and uses it. No setup.
- **WebLLM** — open the **engine panel** (click the engine badge) and tap *Download & enable
  WebLLM*. This fetches small open model weights (~1 GB, e.g. Llama-3.2-1B) and runs them via
  WebGPU. Requires WebGPU + ~6 GB RAM. Conversation content stays on-device.
- **Fallback** — any other browser uses deterministic regex/heuristics (dates, `@mentions`,
  `"by Friday"`, `"please"`, `"deadline"`, `?`) with a clear "Rule-based" badge.

## Deployment

The app is a static SPA. Best options:

- **GitHub Pages** (zero config) — a workflow at
  `.github/workflows/deploy.yml` builds and deploys `dist/` on every push to `main`.
  In repo *Settings → Pages* set source to *GitHub Actions*. The `base: "./"` config makes the
  build work under any sub-path.
- **Vercel / Netlify** — import the repo; build command `npm run build`, output `dist` (Netlify
  needs `base = \"/\"` or `npm_config_base=/` for root paths; GitHub Pages above is the simplest).

## Extensions (3 ideas)

1. **Voice digest** — a "play the summary" button using the Web Speech API (off-device-free)
   to read the TL;DR and top priorities aloud while you commute.
2. **Multi-chat inbox** — keep several imported chats in IndexedDB, rank them by "missed urgency"
   (highest-priority unanswered item across all groups) like a lean inbox.
3. **Smart notifications** — a periodic checker that re-wardens the current chat window and shows
   an OS notification when a new High-priority item or direct mention arrives (still fully local).
